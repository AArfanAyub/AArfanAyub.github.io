Scope

One app for the whole business

The spreadsheet a small business actually runs on — replaced, not supplemented.

💰Finance

Chart of accounts, journals, invoices, bills, credit notes and payments. Trial balance, profit and loss, balance sheet, general ledger and fiscal periods — all from the same ledger the other modules post into.

📦Inventory

Products, units of measure and warehouses. Stock moves and FIFO cost layers with valuation — so the current quantity is derived from movements, never typed in as a number.

🛒Purchasing

Vendors, purchase orders and goods receipts, with a three-way match against the bill — and tolerances, so a small rounding difference does not block a payment.

🧾Sales

Customers, quotations, sales orders and deliveries, with price lists and credit limits enforced before an order is confirmed.

🤝CRM

Accounts, contacts, leads with one-click conversion, deals on a kanban pipeline, activities and analytics — sitting next to the sales orders they turn into.

🗂️Data & control

Import wizard and CSV export, custom fields, numbering, taxes and currencies, backup/restore and archive. Users, roles and permissions, and a hash-chained audit log over every mutation.

The part that matters

Rules the database will not let you break

The invariants an accountant checks first — enforced in one place, proven by a test each.

Most small-business software is a set of screens over a database that trusts the screens. That works until two features disagree about what a number means.

In NEXUS the rules live in the data layer: nothing posts unbalanced, a posted document is immutable and corrected only by reversal, document numbers are gapless, stock is derived from moves, and every mutation lands in the audit log. docs/QA-RULES.md lists all twenty-five, each with the test that proves it.

Build

From source to installer

  1. git clone https://github.com/AArfanAyub/nexus and enter the folder.
  2. npm install — zero native compilation, so no build tools are needed.
  3. npm run dev — Vite, the TypeScript watcher, the preload bundle and Electron, together.
  4. npm test — 128 assertions, no Electron required.
  5. npm run dist — an NSIS installer and a portable .exe into release/.

If npm run dist fails on a symlink-privilege error, it is Windows, not the app: enable Developer Mode, or build with -c.win.signAndEditExecutable=false. Copy %APPDATA%\nexus\nexus.db and you have a backup — but prefer Settings → Backup, which also verifies the checksum on restore.

Straight answers

Four things worth knowing

🪟Windows x64 only

The build targets Windows 10/11 x64. macOS and Linux run from source but are not tested, so treat them as experimental.

⚠️No code signing

There is no signing certificate, so SmartScreen will warn on first run of a build you make yourself. The warning is expected and does not indicate a problem with the file.

👤One user at a time

NEXUS takes a single-instance lock and refuses to run twice. It is a desktop product, not a shared server — two people cannot work in the same file at once.

📄Proprietary licence

The source is public but not open source: it is under the NEXUS Proprietary Perpetual License, all rights reserved. The community edition is complete for its module set, with no expiry and no nag screen.
